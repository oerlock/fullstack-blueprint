# 全局异常定义与处理

项目内自定义异常统一继承 `AppError`，由全局异常处理器统一转换为 HTTP 响应。

## 错误码规范

应用错误码采用六位整数，前三位对应 HTTP 状态码，后三位用于区分具体异常。Web 会根据错误码自动转换 HTTP 状态码。

| 错误码范围 | HTTP 状态码 | 示例 |
|---|---:|---|
| `400000–400999` | 400 | `400001` 参数无效 |
| `401000–401999` | 401 | `401001` 认证失败 |
| `403000–403999` | 403 | `403001` 权限不足 |
| `404000–404999` | 404 | `404001` 账号不存在 |
| `409000–409999` | 409 | `409001` 积分不足 |
| `422000–422999` | 422 | `422001` 数据校验失败 |
| `429000–429999` | 429 | `429001` 请求频率超限 |
| `500000–500999` | 500 | `500001` 内部错误 |
| `502000–502999` | 502 | `502001` 上游服务错误 |
| `503000–503999` | 503 | `503001` 依赖服务不可用 |

## 异常使用规范

- **直接使用通用异常**：业务代码直接抛出 `backend/errors/codes.py` 中的异常类（如 `AENotFound`、`AEConflict`），子应用内不定义自己的异常类。
- **新增通用异常**：现有类不够用时，在 `backend/errors/codes.py` 中定义较为通用的异常；`code` 与现有类相同的，不单独建类，用 `message` 区分场景即可。
- **消息按需传入**：默认 message 足够时裸抛（`raise AENotFound`）；需要说明具体场景时传 `message`（`raise AENotFound(message="线程不存在")`），携带标识符便于定位（如 `f"Checkpoint 不存在: {checkpoint_id}"`）。
- **双继承标记**：异常需同时被 `except` 按领域捕获时，可继承 AE* 类与领域异常基类，如 `class X(AENotFound, AIModelConfigError)`。

## 异常处理约定

- **错误码**：不得重复分配，已使用的错误码应保持含义稳定。
- **统一响应**：包含 `code`、`message`、`metadata`。
- **未预期异常**：记录服务端日志，统一返回 `500001`，不暴露内部实现细节。
- **业务代码**：直接抛出对应异常，由全局异常处理器统一处理，不要在路由层捕获后再转 `HTTPException`。
